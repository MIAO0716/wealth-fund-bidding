# 接口说明（API v1）

所有接口前缀 `/api/v1`，请求与响应均为 JSON（上传、模板、导出除外）。

## 通用约定

- **写请求必须带请求头** `x-bidding-client: 1`（防跨站伪造）。
- **身份**：管理员、领导、大屏各用独立的 HttpOnly Cookie（`bid_admin` / `bid_unit` / `bid_screen`），浏览器自动携带。
- **金额**：一律十进制字符串，单位万元（如 `"135.00"`）；`targetFen` 为人民币分的整数字符串。
- **增幅**：整数百分点，`35` 表示 35%。
- **幂等**：所有现场写操作带 `idempotencyKey`（8–128 位，客户端每次「确认」生成一个新的）。相同键 + 相同内容返回原结果（`replayed: true`），相同键 + 不同内容返回 `IDEMPOTENCY_CONFLICT`。
- **错误格式**：

```json
{ "error": { "code": "VERSION_CONFLICT", "message": "当前增幅已更新，请重新确认", "details": { "currentPp": 35, "bidVersion": 1 } } }
```

| 错误码 | 手机端提示 |
| --- | --- |
| `PROJECT_NOT_ACTIVE` | 当前项目尚未开放 |
| `PROJECT_PAUSED` | 竞标已暂停，请等待工作人员 |
| `PROJECT_LOCKED` | 本项目已结束，不能追加 |
| `GROUP_NOT_OPEN` | 尚未轮到本组，或本组已结束 |
| `BASE_NOT_ACKNOWLEDGED` | 请先确认认领基础底标 |
| `INVALID_STEP` | 追加后的增幅不符合规则（非整数或低于组别最低增幅） |
| `NOT_GREATER` | 新增幅必须高于已确认增幅 |
| `VERSION_CONFLICT` | 当前增幅已更新，请重新确认 |
| `IDEMPOTENCY_CONFLICT` | 请求标识冲突，请刷新并重新确认 |
| `SESSION_INVALID` | 会话失效，请联系工作人员重新扫码 |
| `HIGH_VALUE_CONFIRM_REQUIRED` | 增幅较大，请再次明确确认（带 `confirmHighValue: true` 重新提交，不是上限） |

其他：`CONTROL_VERSION_CONFLICT`、`DRAFT_VERSION_CONFLICT`、`PROJECT_ORDER`、`ROUND1_INCOMPLETE`、`CONFIG_INCOMPLETE`、`REASON_REQUIRED`、`CONFIRM_REQUIRED`、`DEMO_ONLY`、`READ_ONLY` 等，见 `packages/shared/src/errors.ts`。

## 登录与凭证

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/admin/login` | `{username, password}` |
| POST | `/auth/admin/logout` | |
| GET | `/auth/admin/me` | |
| POST | `/auth/bidder/exchange` | `{token}`：二维码 `/join#t=…` 中的凭证换取单位会话（可重复扫码；新会话让本单位其他会话下线） |
| POST | `/auth/screen/exchange` | `{key}`：大屏链接 `/screen#k=…` 中的只读凭证换取大屏会话 |

凭证放在 URL 的 `#` 片段里，不会出现在服务器或代理日志中；前端交换成功后立即从地址栏移除。

## 首轮数据（管理员）

### 校验

`POST /admin/events/{eventId}/first-round/imports/validate`

```json
{
  "mode": "upsert",
  "rows": [
    {
      "projectCode": "wealth",
      "unitCode": "PD",
      "unitName": "浦东",
      "baseTargetWan": "100.00",
      "firstRoundIncreasePp": 30,
      "remark": "仅接口示例，非正式数据"
    }
  ]
}
```

> 以上 100 万元、30% 仅为字段说明示例，不是正式数据。

响应要点：`validationId`（有效 15 分钟，仅全部通过时返回）、`valid`、`draftVersion`、每行 `status / errors / action（CREATE|UPDATE|UNCHANGED） / previewTargetWan / previous`、`completenessAfter`。

文件上传：`POST /admin/events/{eventId}/first-round/imports/upload`（multipart，字段 `file`，`.xlsx` 或 `.csv`），返回同样结构，另含 `skippedBlank`（底标与增幅都空的模板行被跳过的数量）。

### 提交

`POST /admin/events/{eventId}/first-round/imports/commit`

```json
{ "validationId": "…", "expectedDraftVersion": 3, "idempotencyKey": "客户端生成的唯一请求标识" }
```

提交时重新核验权限、草稿版本、项目未发布与全部校验；任意一行错误整批拒绝。成功返回 `batchId / committedAt / source / operator / draftVersion`。

### 手动录入

`PUT /admin/events/{eventId}/first-round/drafts/{projectCode}/{unitCode}`

```json
{ "baseTargetWan": "100.00", "firstRoundIncreasePp": 30, "remark": "", "expectedDraftVersion": 3, "idempotencyKey": "…" }
```

### 模板与读取

- `GET /admin/first-round/template.xlsx`、`GET /admin/first-round/template.csv`：空白 32 行模板。
- `GET /admin/events/{eventId}/first-round`：草稿、管理预览、已发布快照、导入批次。

### 冻结首轮（会前准备）

`POST /admin/events/{eventId}/first-round/publish`：理财、基金一起冻结（推荐）。

```json
{ "expectedDraftVersion": 5, "idempotencyKey": "…", "confirm": true }
```

`expectedDraftVersion` 为活动级草稿版本（`GET /first-round` 返回的 `draftVersion`）。两个项目都 16 家完整有效、活动名称与日期已填写才会冻结，任一不满足则都不冻结；原子写入快照并初始化当前增幅。冻结后当前专场为理财，大屏切到理财首轮。

`POST /admin/events/{eventId}/projects/{projectCode}/publish-first-round`：单独冻结一个项目（保留接口，`expectedDraftVersion` 为项目草稿版本）。

基金首轮可在会前冻结，但**基金开始竞标要求理财已锁定**（`PROJECT_ORDER`）；理财锁定后当前专场自动转到基金。

## 现场控制（管理员）

`POST /admin/events/{eventId}/projects/{projectCode}/control`

```json
{ "action": "OPEN_GROUP", "groupNo": 2, "expectedControlVersion": 7, "idempotencyKey": "…" }
```

| action | 说明 |
| --- | --- |
| `START` | `ROUND1_PUBLISHED → LIVE`；可带 `groupNo` 同时开放该组 |
| `OPEN_GROUP` | 开放一个组（同时最多一个）；重新开放已结束组需 `reason` |
| `CLOSE_GROUP` | 结束当前组；最后一组结束后自动暂停 |
| `PAUSE` / `RESUME` | `LIVE ↔ PAUSED` |
| `LOCK` | 仅从 `PAUSED` 执行，需 `confirm: true`；生成不可变结果快照，返回 `tieWarnings` |

- `GET /admin/events/{eventId}/projects/{projectCode}/lock-preview`：锁定前的并列提示。
- `POST /admin/events/{eventId}/projects/{projectCode}/units/{unitCode}/base-ack`：代记底标确认，`{idempotencyKey}`（`reason` 选填）。
- `POST /admin/events/{eventId}/projects/{projectCode}/units/{unitCode}/bids`：代录加码，与领导端同一校验（`reason` 选填）。
- `POST /admin/events/{eventId}/projects/{projectCode}/units/{unitCode}/correct`：工作人员更正（下调），`{targetIncreasePp, expectedBidVersion, idempotencyKey}`。目标须为整数、低于当前增幅、不低于首轮增幅；竞标开始后至锁定前可用（含本组结束、暂停时）。流水来源 `ADMIN_CORRECTION`，实时事件 `BID_CORRECTED`，错误码 `NOT_LOWER`。
- `POST /admin/events/{eventId}/screen-mode`：`{mode: FIRST_ROUND|LIVE|RESULTS, projectCode}` 切换大屏。

## 领导端

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/bidder/session` | 当前会话绑定的活动与单位 |
| GET | `/bidder/events/{eventId}/me` | 仅本单位数据 + 当前专场信息，带 `seq` |
| POST | `/bidder/events/{eventId}/projects/{projectCode}/base-ack` | `{idempotencyKey}` 确认认领基础底标 |
| POST | `/bidder/events/{eventId}/projects/{projectCode}/bids` | 提交追加 |
| GET | `/bidder/events/{eventId}/requests/{idempotencyKey}` | 回执核验 |
| GET | `/bidder/events/{eventId}/stream?since={seq}` | SSE |

提交追加：

```json
{ "targetIncreasePp": 35, "expectedBidVersion": 4, "idempotencyKey": "每次点击确认时生成的唯一标识" }
```

发送「最终确认增幅」而不是增量；单位只取自会话。成功（201）：

```json
{
  "receipt": {
    "bidId": "…", "receiptNo": "LC-PD-005-128", "unitCode": "PD", "projectCode": "wealth",
    "fromPp": 30, "toPp": 35, "deltaPp": 5,
    "baseTargetWan": "100.00", "targetWan": "135.00", "targetFen": "135000000",
    "bidVersion": 5, "eventSequence": 128, "acceptedAt": "2026-10-10T02:15:03.120Z", "source": "LEADER"
  },
  "replayed": false
}
```

网络超时时，先 `GET /bidder/events/{eventId}/requests/{idempotencyKey}`：`SUCCEEDED`（附原回执）、`FAILED`（附原错误）或 `NOT_FOUND`（请求未到达服务器，可用同一键重试）。

## 大屏（只读）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/screen/session` | |
| GET | `/screen/events/{eventId}/live?project=wealth` | 三组实时榜 + 最近 5 条加码；首轮未发布时不返回榜单 |
| GET | `/screen/events/{eventId}/projects/{projectCode}/first-round` | 仅返回已发布首轮；未发布返回 `published: false` 且无榜单 |
| GET | `/screen/events/{eventId}/results` | 两项目锁定结果 |
| GET | `/screen/events/{eventId}/stream?since={seq}` | SSE |

## 实时推送（SSE）

1. 先取带 `seq` 的快照，再以 `?since={seq}` 订阅。
2. 事件：`hello`（`headSeq`）、`message`（`RealtimeMessage`，带 `id: seq`）、`heartbeat`（每 15 秒，含 `lastSeq`）、`resync`（客户端序列超前，须重新取快照）。
3. 断线重连时浏览器自动带 `Last-Event-ID`，服务端从该序列之后按序补发。
4. 权限裁剪：领导只收项目级消息和本单位消息；大屏只收公开消息；管理员收全部。

`RealtimeMessage`：

```json
{ "seq": 128, "type": "BID_ACCEPTED", "projectCode": "wealth", "unitCode": "PD", "serverTime": "…", "data": { "fromPp": 30, "toPp": 35, "bidVersion": 5 } }
```

类型：`BID_ACCEPTED`、`BASE_ACKNOWLEDGED`、`PROJECT_STATUS`、`GROUP_STATUS`、`FIRST_ROUND_PUBLISHED`、`PROJECT_LOCKED`、`DRAFT_UPDATED`（仅管理员）、`EVENT_UPDATED`、`SCREEN_MODE`、`SESSION_CHANGED`（仅管理员）。

## 其他管理接口

- 活动：`GET/POST /admin/events`、`GET /admin/events/{id}`、`PATCH /admin/events/{id}/config`、`GET /admin/events/{id}/readiness`、`GET /admin/events/{id}/state`。
- 新建关联活动（发布后发现基础数据错误时）：`POST /admin/events`，`{config, parentEventId, parentReason}`。
- 二维码：`GET /admin/events/{id}/units`（含 `online`）、`POST /admin/events/{id}/units/{unit}/credentials`（每家一个固定二维码：已有则返回同一个，没有才生成；`{renew:true}` 才重新生成，管理端界面不提供）、`POST /admin/events/{id}/credentials/batch`（16 家，同上）、`POST /admin/events/{id}/units/{unit}/kick`（强制下线：当前手机下线，二维码继续有效）、`POST /admin/events/{id}/units/{unit}/revoke`（作废：手机下线且该单位二维码全部作废）。二维码有效期内可重复扫码，新手机登录会让本单位其他手机下线。
- 删除活动：`POST /admin/events/{id}/delete` `{confirm:true}`，删除该活动全部数据（不可恢复）；竞标进行中返回 `INVALID_STATE`；配置备份目录时先生成检查点。全局审计记 `EVENT_DELETED`。
- 大屏在线数：`GET /screen/events/{id}/presence` → `{online, total}`（有实时连接或断开不足 1 分钟的领导单位数）。
- 大屏凭证：`GET/POST /admin/events/{id}/screen-keys`、`POST /admin/events/{id}/screen-keys/{keyId}/revoke`。
- 监控与审计：`GET /admin/events/{id}/monitor`、`GET /admin/events/{id}/audit`、`GET /admin/events/{id}/stream`。
- 演示：`POST /admin/events` 带 `{isDemo: true}` 创建并填充演示数据；`POST /admin/events/{id}/demo/seed` 仅演示活动可用。
- 健康检查：`GET /healthz`。
