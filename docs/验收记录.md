## 尚需在正式使用前完成（需真实设备/环境）

1. **真机测试**：至少 2 部手机（iPhone 微信内置浏览器、安卓微信/Chrome 各一）、1 台管理电脑、1 台投屏电脑，同单位两部手机并发、扫码、两步确认、断网恢复。自动化测试使用的是 Chromium 模拟手机视口，不能替代微信内置浏览器实测。
2. **会场网络**：按《部署说明》检查 AP 隔离、端口、固定 IP，并在会场网络下跑一次 `npm run perf`。
3. **投影效果**：在实际投影仪/LED 屏上检查字号、对比度（设计基准 1920×1080，其他比例等比缩放并留边）。
4. **Docker 部署**：开发环境无 Docker 守护进程，Dockerfile 与 compose 文件未实际构建；请在目标服务器构建并彩排一次。
5. **组织者确认的政策**：业务口径、是否只允许 +5、并列第一如何授旗、无人达到 30% 是否空缺——系统已按需求文档保守处理，确认后只需修改配置或现场按流程操作。

## 已知限制

- 单进程部署（需求明确不需要微服务）；多实例部署时实时推送依赖 PostgreSQL LISTEN/NOTIFY，已支持，但未做多实例压测。
- 大屏「领先变化」提示与加码高亮依赖浏览器收到推送；降级为轮询时仍会更新数据，但高亮可能不出现。
- 二维码为一次性凭证：领导换浏览器（如从微信切到 Safari）需工作人员重发。
- Playwright 在本环境中对中文附件名的 `suggestedFilename()` 返回 `download`，测试改为直接校验响应头与文件内容；浏览器实际下载使用 `filename*` 中文文件名（另附 ASCII 兜底名）。
