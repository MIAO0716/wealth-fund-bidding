# 云服务器部署（互联网版）

与 [Windows 一键部署包（局域网版）](本机体验.md) 相互独立：程序功能完全相同，部署方式、运行环境和数据分开，可以同时存在。

| | 局域网版（Windows 一键部署包） | 互联网版（云服务器部署包） |
| --- | --- | --- |
| 运行在 | 会场的一台 Windows 电脑 | 云服务器（Ubuntu/Debian） |
| 领导手机 | 必须连会场同一个 Wi-Fi | 用手机流量或任意网络，**无需连 Wi-Fi** |
| 访问地址 | `http://电脑局域网IP:8080` | `https://你的域名` |
| HTTPS | 无 | 自动申请免费证书并续期 |
| 前提 | 一台电脑 | 云服务器 + 域名（中国大陆需 ICP 备案） |
| 下载 | Releases 中的 `BiddingSystem-windows-x64.zip` | Releases 中的 `BiddingSystem-linux-x64.tar.gz` |

## 〇、不备案的做法（香港服务器，推荐本次采用）

中国大陆的云服务器，未备案的域名无法使用 80/443 端口；**香港服务器不需要 ICP 备案**，买好当天即可使用，手机流量访问延迟通常 30–80 毫秒，对竞标没有影响。

| 步骤 | 做什么 | 用时 |
| --- | --- | --- |
| 1 | 购买香港「轻量应用服务器」：腾讯云或阿里云均可，**2 核 2G 或 2 核 4G**，系统 **Ubuntu 22.04**，地域选**中国香港** | 10 分钟 |
| 2 | 控制台「防火墙」放行 TCP **22、80、443** | 2 分钟 |
| 3 | 用 IP 先装一遍试运行：`sudo ./install.sh --domain 服务器IP --tls none`，手机流量扫码走一遍流程 | 15 分钟 |
| 4 | （建议）购买一个域名并完成实名认证，添加 A 记录指向服务器 IP；香港服务器不需要备案 | 实名认证通常数小时到 1–3 个工作日 |
| 5 | 有了域名后重新运行 `sudo ./install.sh --domain 你的域名 --email 你的邮箱`，自动启用 HTTPS（数据保留） | 5 分钟 |
| 6 | 在新地址下重新发放领导二维码与大屏链接（二维码里写的是访问地址），iPhone、安卓各一台关闭 Wi-Fi 实测 | 30 分钟 |

- 只用 IP + HTTP 也能用，但微信打开时更容易出现「非微信官方网页」提示（领导点「继续访问」即可），且没有 HTTPS 加密。正式活动建议用域名 + HTTPS。
- **领导使用卡推荐用手机自带相机扫码**：打开的是手机自带浏览器，不经过微信，不受微信对未备案域名的提示或拦截影响；相机扫不出时再用微信「扫一扫」。
- 金山文档读取在云服务器上同样可用（服务器能访问 kdocs.cn 即可）。

## 一、准备（大陆服务器需提前 1–3 周备案）

1. **云服务器**：阿里云 / 腾讯云 / 华为云等，2 核 2G 及以上，系统选 **Ubuntu 22.04 或 24.04**（x86_64）。
2. **域名**：例如 `bid.example.com`。在域名解析中添加 **A 记录**，指向服务器公网 IP。
3. **ICP 备案（中国大陆服务器必需）**：在云厂商后台申请，通常 1–3 周。未备案的域名在大陆服务器上无法访问 80/443 端口，且微信内可能被拦截。
   - 时间来不及：可选择**香港或海外服务器**（无需备案，访问略慢）；微信内若提示「非微信官方网页」，领导可点右上角「在浏览器打开」。
4. **安全组 / 防火墙**：在云控制台放行 TCP **22、80、443**。
5. **合规**：如单位对公网系统有备案、等保或数据存放要求，请先与信息科技部门确认。本系统不涉及客户信息，但包含各单位的业务目标数据。

## 二、安装（约 3 分钟）

1. 打开仓库的 **Releases**，下载最新的「云服务器部署包」`BiddingSystem-linux-x64.tar.gz`。
2. 上传到服务器（`scp`，或云控制台的文件上传），登录服务器执行：

   ```bash
   tar xzf BiddingSystem-linux-x64.tar.gz
   cd BiddingSystem-linux-x64
   sudo ./install.sh --domain bid.example.com --email you@example.com
   ```

3. 按提示设置管理员密码（账号 `admin`，至少 10 位）。
4. 浏览器打开 `https://bid.example.com/admin` 登录。

安装脚本自动完成：

- 安装 PostgreSQL、Nginx、Certbot（均来自系统软件源，不依赖 Docker Hub 或 npm）；程序自带 Node.js；
- 数据库只监听本机、随机强密码；程序只监听本机，由 Nginx 对外提供 HTTPS；
- 申请 Let's Encrypt 免费证书并自动续期，HTTP 自动跳转 HTTPS；
- 注册系统服务：开机自启、异常自动重启；
- 每天 03:30 自动备份（保留 30 份），首轮发布、项目锁定后也会自动生成检查点；
- 实时推送（SSE）所需的 Nginx 设置（关闭缓冲、长连接超时）。

## 三、日常管理

| 命令 | 作用 |
| --- | --- |
| `sudo bidding status` | 运行状态、访问地址、最近备份 |
| `sudo bidding logs` / `logs -f` | 查看 / 持续跟踪日志 |
| `sudo bidding restart` | 重启 |
| `sudo bidding backup` | 立即备份 |
| `sudo bidding backups` | 列出备份 |
| `sudo bidding restore 备份文件` | 从备份恢复（先自动备份当前数据，恢复后领导与大屏需重新扫码） |
| `sudo bidding reset-admin` | 重置管理员密码 |
| `sudo bidding readonly on/off` | 只读维护模式 |

- 数据与备份：`/var/lib/bidding`（备份在 `backups/`）。会前、会后各执行一次 `sudo bidding backup`，并把备份文件下载到本地电脑保存一份。
- 配置：`/etc/bidding/bidding.env`（修改后 `sudo bidding restart`）。

## 四、升级

下载新版本上传并解压，在新目录中执行 `sudo ./install.sh`（无需参数，沿用原域名、配置与数据）。旧版本保留在 `/opt/bidding/releases`，最多保留 3 个。

## 五、现场使用的区别

- 领导**不需要连会场 Wi-Fi**，用手机流量扫码即可。管理端「准备与配置」中的 Wi-Fi 两项**留空**，领导使用卡上就不会出现 Wi-Fi 步骤。
- 大屏电脑、管理电脑只要能上网即可，不必与领导手机在同一网络。
- 会场网络不稳定时，手机流量与会场网络互为备份；会前仍建议用 `scripts`/压测在会场网络下测一次。

## 六、安全措施

- 全站 HTTPS + HSTS；内容安全策略（CSP）只允许加载本站资源；禁止被其他网站嵌入。
- 管理员登录防暴力破解：同一账号连续输错 5 次锁定 15 分钟。
- 领导二维码一次性使用、绑定手机；会话只能访问本单位数据；凭证不出现在服务器日志中。
- 数据库、程序均不对公网开放端口；系统服务以独立的低权限用户运行。

## 七、常见问题

| 现象 | 处理 |
| --- | --- |
| 证书申请失败 | 检查：域名是否已解析到本服务器；安全组是否放行 80/443；大陆服务器是否已备案。处理后重新运行 `install.sh` |
| 微信里打不开 | 改用手机自带相机扫码（直接用手机浏览器打开）；或在微信里点右上角「在浏览器打开」。换了浏览器的领导需工作人员重新发码 |
| 大屏一直显示「降级刷新」 | 中间有代理/CDN 缓冲了实时推送；不要在本系统前加 CDN，或为 `/api/v1/*/stream` 关闭缓冲 |
| 忘记管理员密码 | `sudo bidding reset-admin` |

## 八、验证方式

每个云服务器部署包都由 GitHub 的 Ubuntu 构建机**真实执行 `install.sh`**（systemd + Nginx + 自签名 HTTPS）后发布，并自动验证：HTTP 跳转 HTTPS、HSTS、数据库与程序不对外监听、经 Nginx 的实时推送、发布首轮→扫码→认领→加码→导出→锁定、重启后数据保留、备份恢复、重新运行安装脚本升级、重置密码、只读维护模式。
真实域名的 Let's Encrypt 证书申请无法在构建机上验证，首次上线时请留意安装输出。
