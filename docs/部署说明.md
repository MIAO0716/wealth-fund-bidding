# 部署说明

系统为单进程 Node.js 服务 + PostgreSQL，前端由同一服务同域托管。

> **会场 Windows 电脑请直接使用[一键部署包](本机体验.md)**（内置 Node.js 与 PostgreSQL，双击启动）；**云服务器请使用[云服务器部署包](云服务器部署.md)**（一条命令安装）。以下为 Docker 与手动部署说明。

支持两种部署方式：**互联网 HTTPS 部署（推荐正式使用）** 与 **会场局域网部署**。

## 一、环境要求

| 项目 | 要求 |
| --- | --- |
| Node.js | ≥ 22.9（使用 Docker 时无需单独安装） |
| PostgreSQL | ≥ 14，推荐 16 |
| pg_dump / pg_restore / psql | 与数据库同大版本，用于备份恢复 |
| 服务器 | 2 核 2G 即可满足 16 家单位、2 块大屏、1 个管理端 |

## 二、关键配置（`.env`）

完整说明见 [`.env.example`](../.env.example)。最重要的三项：

- `DATABASE_URL`：数据库连接串。
- `PUBLIC_BASE_URL`：**二维码中写入的地址**，必须是手机能访问到的地址。互联网部署写 `https://bid.example.com`；局域网部署写 `http://192.168.1.10:8080`。**不能写 localhost**，否则手机扫码打不开。
- `BACKUP_DIR`：自动检查点目录。配置后，每次首轮发布、项目锁定后自动 `pg_dump`。

## 三、方式 A：Docker Compose（推荐）

```bash
cp .env.example .env
# 编辑 .env：至少设置 DB_PASSWORD、PUBLIC_BASE_URL；位于 Nginx 之后时设 TRUST_PROXY=true
docker compose up -d --build

# 创建管理员（交互输入密码，不落盘）
docker compose run --rm app node apps/server/dist/admin-create.js --username admin --name 工作人员

# 健康检查
curl http://127.0.0.1:8080/healthz
```

- 应用启动时自动执行数据库迁移。
- 自动检查点保存在宿主机 `./backups/`。
- 镜像运行阶段基于官方 `postgres:16` 镜像，以保证 `pg_dump` 版本与数据库一致。
- 本仓库的 Dockerfile 与 compose 文件**未在开发环境实际构建运行过**（开发环境无 Docker 守护进程）；上线前请在目标服务器执行一次 `docker compose up --build` 并完成彩排。

## 四、方式 B：直接运行

```bash
npm ci
npm run build                 # 构建前端与服务端
cp .env.example .env          # 设置 DATABASE_URL、PUBLIC_BASE_URL、WEB_DIST=../web/dist 等
npm run db:migrate
npm run admin:create -- --username admin --name 工作人员
npm start                     # 生产运行（读取根目录 .env）
```

建议用 systemd / pm2 守护进程，并设置开机自启。

## 五、互联网 HTTPS 部署

1. 准备域名与证书，按 [`deploy/nginx.conf`](../deploy/nginx.conf) 配置反向代理。
2. **SSE 长连接**：`/api/v1/**/stream` 必须 `proxy_buffering off`、`proxy_read_timeout 3600s`，否则大屏会延迟或频繁断线。
3. 应用设置 `TRUST_PROXY=true`、`PUBLIC_BASE_URL=https://你的域名`，Cookie 自动启用 Secure。
4. 会前用会场的手机网络（4G/5G、会场 Wi-Fi）和投屏电脑分别打开域名，确认都能访问。

## 六、会场局域网部署

1. 一台电脑或小型服务器运行数据库与应用，**固定 IP**（如 192.168.1.10）。
2. `PUBLIC_BASE_URL=http://192.168.1.10:8080`；生成二维码前确认此地址正确。
3. 检查清单：
   - 手机与投屏电脑连接**同一个可达的 Wi-Fi**；
   - 路由器/AP **关闭客户端隔离（AP 隔离）**；
   - 服务器防火墙放行 8080 端口；
   - 用两部不同品牌手机实测：手机自带相机扫码、微信「扫一扫」两种方式都能打开；
   - 不要在会议中途更换服务器 IP，否则已打印二维码失效。
4. 局域网 http 不是浏览器的「安全上下文」，本系统已避开依赖安全上下文的接口，可正常使用；如需 HTTPS，可在局域网内用自签证书 + Nginx，但需在每部手机信任证书，一般不建议。

## 七、备份与恢复

### 自动检查点

配置 `BACKUP_DIR` 后，以下时机自动生成可恢复检查点，并记录在管理端「导出与备份」页：

- 每次首轮发布后；
- 每次项目锁定后；
- 管理端手动点击「立即生成检查点」。

### 手动备份

```bash
DATABASE_URL=postgres://... BACKUP_DIR=./backups scripts/backup.sh 会前
```

### 恢复（必须停写）

1. 通知现场暂停；在管理端暂停当前项目。
2. 停止应用，或以 `READ_ONLY=true` 重启（只读维护模式下所有写入返回「系统处于只读维护状态」）。
3. 执行恢复：

   ```bash
   DATABASE_URL=postgres://... scripts/restore.sh backups/xxx.dump
   ```

   脚本会：先把当前库再备份一份 → 用检查点覆盖 → **作废所有领导与大屏会话、未使用的二维码**（防止旧会话继续报价）→ 写入恢复记录。
4. 以正常模式重启应用，在管理端重新发放 16 家二维码、重新打开大屏链接。
5. 大屏、手机的旧序列号会被服务端识别并要求重新同步全量快照。

## 八、日志与安全

- 日志不记录 Cookie；二维码凭证在 URL `#` 片段中，不会进入服务器或代理日志。
- 数据库只保存凭证与会话的 SHA-256 哈希；管理员密码使用 scrypt 哈希。
- 前端不依赖外部 CDN 与外部字体，会场断外网时局域网部署仍可完整使用。
- 健康检查：`GET /healthz`（数据库不可用时返回 503）。

## 九、开发与测试环境

| 命令 | 用途 |
| --- | --- |
| `npm run dev:server` / `npm run dev:web` | 开发模式 |
| `npm test` | 规则单元测试 + 服务端集成测试（使用 `TEST_DATABASE_URL`，会被清空） |
| `npm run build && npm run test:e2e` | 多浏览器全流程测试（使用 `bidding_e2e` 库，会被清空） |
| `BASE_URL=… ADMIN_PASSWORD=… npm run perf` | 性能验证（会新建一场演示活动） |
| `npm run templates` | 重新生成 `templates/` 下的空白模板 |
